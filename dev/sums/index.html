Kernel sums

All estimators of the package are built from the sums

\[S_{rj} = \sum_{i=1}^n w_i z_i\, K(u_{ij})\, u_{ij}^r, \qquad u_{ij} = \frac{x_i - p_j}{h_j}, \qquad r = 0, \dots, k_{\max},\]

over the sorted observations $x_i$ with weights $w_i$ and values $z_i$, at the evaluation points $p_j$ with bandwidths $h_j$. For a symmetric kernel, $S_{0j} / (h_j \sum_i w_i)$ is the kernel density estimate at $p_j$, and with $k_{\max} = 2p$, and with $z = y$ and $k_{\max} = p$, the sums give the normal equations of a local polynomial fit of order $p$. kernel_sums returns the $(k_{\max} + 1) \times m$ matrix of these sums, with one bandwidth or one per point, and computes them with one of four engines.

DirectSumsany$O(nm)$exact; the reference

Here $D$ is the degree of the pieces of the kernel. By default the package chooses between WindowSums and FastSums for a polynomial kernel by a model of their costs, which counts the observations in the windows and the blocks that each window spans. For Gaussian kernels it sums over the observations within 38.62 standard deviations, beyond which the kernel is exactly zero in floating point, so that the sums equal those of DirectSums; other kernels use DirectSums.

FastSums uses that on each polynomial piece of the kernel, $S_{rj}$ is a linear combination of power sums of the observations in that piece, which prefix sums give in constant time (Seifert, Brockmann, Engel and Gasser 1994; Langrené and Warin 2019). Power sums about one centre cancel catastrophically when the data are far from zero or the bandwidth is small compared with their range. Therefore, the engine cuts the data into blocks one window wide and stores the prefix sums of each block about its own centre, so that its rounding error stays at about $10^{-13}$ of the weight near the point, whatever the location and the scale of the data. The error of such blocks grows about as $2.6^s$ units of rounding with the highest power $s = D + k_{\max}$ of the sums, so that for $s > 6$ the blocks are narrower: half a window up to $s = 13$ and a quarter up to $s = 20$. BinnedSums splits each value between the two nearest points of a grid with spacing $h/\mathrm{binsperh}$ and sums exactly over the occupied grid points, which suits Gaussian kernels with many observations.

The points are processed in chunks as parallel tasks when Julia runs with several threads, and the sums do not depend on the number of threads. A SumsWorkspace holds buffers that repeated calls, such as those of a bandwidth search, reuse.

KernelSmoothing.BinnedSums — Type
BinnedSums(; binsperh = 50)

Approximate sums from linearly binned data: each observation's value is split between the two nearest points of a grid with spacing h / binsperh, in proportion to its distance from them, and the sums are computed over the occupied grid points. Gaussian kernels are cut off at 12 standard deviations. Useful for Gaussian kernels with many observations, where DirectSums is slow. With a bandwidth per point, the grid spacing uses the smallest bandwidth.

Binning replaces each observation's term by its linear interpolation between grid points, so the relative error is of order binsperh^-2 for continuous kernels, about 1e-3 at the default. For kernels that jump, such as the uniform kernel and the derivatives of the triangular and Epanechnikov kernels, the error comes from the observations within one grid spacing of a jump and decreases much more slowly as binsperh grows.

KernelSmoothing.DirectSums — Type
DirectSums()

Sums over all observations for every point: O(n m) time for n observations and m points, for any kernel. The other engines are tested against it.

source
KernelSmoothing.FastSums — Type
FastSums()

Exact sums for polynomial kernels in O(n + m log m) time, independent of the bandwidth. On each polynomial piece of the kernel the sum is a combination of power sums of the observations, so prefix sums answer every point in constant time (fast sum updating; Seifert et al. 1994, Langrené and Warin 2019).

Power sums about one far-away centre lose all accuracy when the data are far from zero or the bandwidth is small compared with their range. Here the data are split into blocks at most one window wide and the power sums are taken about the midpoint of the observations in each block. The rounding error grows with the width of the blocks and the highest power of the sums, the degree of the kernel plus kmax, so that the blocks narrow as the power grows. The error is then at most about 1e-13 times the total absolute weight of the observations near the point, whatever the location and scale of the data and the bandwidth; for kernels of degree d with d + kmax ≤ 6, such as the named kernels other than the triweight with kmax ≤ 2, the blocks are one window wide. A sum that is much smaller than that, because the kernel nearly vanishes at every observation in the window, has a larger relative error.

With a bandwidth per point, the blocks are sized for the smallest bandwidth, and a point with a larger bandwidth spans more of them.

KernelSmoothing.SumEngine — Type
SumEngine

Supertype of the algorithms that compute kernel_sums. DirectSums, WindowSums and FastSums are exact up to rounding; BinnedSums approximates. isexact tells them apart. All engines work on several points at once when Julia runs with several threads.

source
KernelSmoothing.SumsWorkspace — Type
SumsWorkspace()

Buffers that kernel_sums! can reuse: the values wᵢ zᵢ, the order of the points, the blocks and power sums of FastSums and the grid of BinnedSums. Passing the same workspace to repeated calls, as in a bandwidth search, saves allocating them every time. A workspace must not be used by two calls at the same time.

source
KernelSmoothing.WindowSums — Type
WindowSums()

Sums over the observations in each point's window, which a search in the sorted data finds: O(m log n) time plus the total size of the windows. For compactly supported kernels; it adds the same terms in the same order as DirectSums, so the sums are identical.

KernelSmoothing.kernel_sums — Method
kernel_sums(d::SmoothingData, k, h, points; kmax = 0, z = nothing, engine, workspace)
kernel_sums(d::SmoothingData, k, h; kmax = 0, z = nothing, engine, workspace)

The kernel sums

S[r + 1, j] = ∑ᵢ wᵢ zᵢ k(uᵢⱼ) uᵢⱼ^r,   uᵢⱼ = (xᵢ - points[j]) / hⱼ,   r = 0, …, kmax,

over the observations xᵢ of d with weights wᵢ, as a (kmax + 1) × length(points) matrix. The bandwidth h is a number, or a vector with one bandwidth per point, as pointwise bandwidth selectors give. Without points the sums are evaluated at the observations themselves, d.x, as cross-validation needs. z holds one value per observation in the sorted order of d, such as the responses d.y; by default every zᵢ = 1.

Estimators are built from these sums. For a symmetric kernel, S[1, j] / (h * d.sumw) is the kernel density estimate at points[j]; with kmax = 2p, and with z = d.y and kmax = p, the sums give the normal equations of a local polynomial fit of order p in the scaled variable u.

engine chooses the algorithm. By default it is the faster exact one: for polynomial kernels WindowSums when the windows hold few observations and FastSums otherwise, by a model of their costs; for Gaussian kernels sums over the observations within 38.62 standard deviations, beyond which the kernel underflows to zero, so that they equal DirectSums exactly; and DirectSums for other kernels. BinnedSums approximates. A SumsWorkspace passed as workspace provides reusable buffers. Gaussian derivatives whose cached scale factor overflows or vanishes use full sums.

Examples

julia> d = SmoothingData([0.0, 0.5, 1.0]);

julia> kernel_sums(d, EpanechnikovKernel(), 1.0, [0.5]; kmax = 2)
