Kernel sums

KernelSmoothing.BinnedSums — Type
BinnedSums(; binsperh = 50)

Approximate sums from linearly binned data: each observation's value is split between the two nearest points of a grid with spacing h / binsperh, in proportion to its distance from them, and the sums are computed over the occupied grid points. Gaussian kernels are cut off at 12 standard deviations. Useful for Gaussian kernels with many observations, where DirectSums is slow. With a bandwidth per point, the grid spacing uses the smallest bandwidth.

Binning replaces each observation's term by its linear interpolation between grid points, so the relative error is of order binsperh^-2 for continuous kernels, about 1e-3 at the default. For kernels that jump, such as the uniform kernel and the derivatives of the triangular and Epanechnikov kernels, the error comes from the observations within one grid spacing of a jump and decreases much more slowly as binsperh grows.

KernelSmoothing.DirectSums — Type
DirectSums()

Sums over all observations for every point: O(n m) time for n observations and m points, for any kernel. The other engines are tested against it.

source
KernelSmoothing.FastSums — Type
FastSums()

Exact sums for polynomial kernels in O(n + m log m) time, independent of the bandwidth. On each polynomial piece of the kernel the sum is a combination of power sums of the observations, so prefix sums answer every point in constant time (fast sum updating; Seifert et al. 1994, Langrené and Warin 2019).

Power sums about one far-away centre lose all accuracy when the data are far from zero or the bandwidth is small compared with their range. Here the data are split into blocks one window wide and the power sums are taken about the centre of each block. The rounding error is then about 1e-13 times the total absolute weight of the observations near the point, whatever the location and scale of the data. A sum that is much smaller than that, because the kernel nearly vanishes at every observation in the window, has a larger relative error.

With a bandwidth per point, the blocks are one window wide at the smallest bandwidth, and a point with a larger bandwidth spans more of them.

KernelSmoothing.SumEngine — Type
SumEngine

Supertype of the algorithms that compute kernelsums. DirectSums, WindowSums and FastSums are exact up to rounding; BinnedSums approximates. isexact tells them apart. All engines work on several points at once when Julia runs with several threads.

source
KernelSmoothing.SumsWorkspace — Type
SumsWorkspace()

Buffers that kernelsums! can reuse: the values wᵢ zᵢ, the order of the points, the blocks and power sums of FastSums and the grid of BinnedSums. Passing the same workspace to repeated calls, as in a bandwidth search, saves allocating them every time. A workspace must not be used by two calls at the same time.

source
KernelSmoothing.WindowSums — Type
WindowSums()

Sums over the observations in each point's window, which a search in the sorted data finds: O(m log n) time plus the total size of the windows. For compactly supported kernels; it adds the same terms in the same order as DirectSums, so the sums are identical.

KernelSmoothing.kernelsums — Method
kernelsums(d::SmoothingData, k, h, points; kmax = 0, z = nothing, engine, workspace)
kernelsums(d::SmoothingData, k, h; kmax = 0, z = nothing, engine, workspace)

The kernel sums

S[r + 1, j] = ∑ᵢ wᵢ zᵢ k(uᵢⱼ) uᵢⱼ^r,   uᵢⱼ = (xᵢ - points[j]) / hⱼ,   r = 0, …, kmax,

over the observations xᵢ of d with weights wᵢ, as a (kmax + 1) × length(points) matrix. The bandwidth h is a number, or a vector with one bandwidth per point, as pointwise bandwidth selectors give. Without points the sums are evaluated at the observations themselves, d.x, as cross-validation needs. z holds one value per observation in the sorted order of d, such as the responses d.y; by default every zᵢ = 1.

Estimators are built from these sums. For a symmetric kernel, S[1, j] / (h * d.sumw) is the kernel density estimate at points[j]; with kmax = 2p, and with z = d.y and kmax = p, the sums give the normal equations of a local polynomial fit of order p in the scaled variable u.

engine chooses the algorithm. By default it is the faster exact one: for polynomial kernels WindowSums when the windows hold few observations and FastSums otherwise, and DirectSums for other kernels. BinnedSums approximates. A SumsWorkspace passed as workspace provides reusable buffers.

Examples

julia> d = SmoothingData([0.0, 0.5, 1.0]);

julia> kernelsums(d, EpanechnikovKernel(), 1.0, [0.5]; kmax = 2)
3×1 Matrix{Float64}:
 1.875
 0.0
 0.28125
